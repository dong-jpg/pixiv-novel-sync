## 目标与执行原则

1. 所有业务任务在部署主机执行，支持 NAS 单容器运行；远程云机方案退役。
2. 保留现有任务身份、时区、优先级、水位、取消、分析预算和来源校验；无需另建队列框架。
3. 优化长篇、大库和空闲开销，以读取次数、事务长度及正确性测试衡量。
4. 共享功能先在 main 修改；ai-writing 的合并与验证单独处理，不覆盖其写作实现。
5. 文档只维护使用指南、当前契约、设计、实施计划和状态；代码验证与生产启用分别判断。

## 当前实施与验收

### L1 本地执行

- 移除远程包、CLI、控制器/worker/出口/签到、网页与认证豁免；同步直接使用原 Pixiv 客户端，AI 直接使用原 Provider。
- 保留单本抓取规范化、错误页识别、小说身份、摘要及附件校验，移除远程传输编解码。
- 旧 `sync.pixiv_execution=remote`、`PIXIV_REMOTE_*` 和 `INSTABOX_API_KEY` 不影响本地执行；设置页不再提供执行位置选择，保存时清理旧 YAML 键。
- 现有取消、部分失败、重试、限速、水位、归档和分析预算回归必须通过。旧队列不重放，不增加 AI 请求预算。

### N1 NAS / Docker

- 单容器单进程 Waitress + 调度器，镜像面向 amd64/arm64；不支持多个副本共享书库。
- 挂载完整配置和数据目录，固定会话及 AI 密钥；非 root 用户启动前检查配置、访问密码和目录写权限。
- 默认手动 Token / Cookie，可选构建 Chromium 自动登录依赖；日志轮换，健康检查只探 Web。
- 迁移停止所有旧写入方，一致复制 SQLite/WAL、归档与密钥；检查旧绝对路径和容器网络，再做小规模真实同步。
- 当前没有 Docker 引擎，镜像构建、Compose 启动、架构及 NAS 权限在目标设备验收。操作指南只维护在 [DOCKER.md](DOCKER.md)。

## 继续保留的质量约束

### X1 逐条结论纠错

按报告身份、结论标识和版本修改可信标记，不覆盖模型原文或代替用户推断喜好。跨报告 ID、过期版本、迟到响应、报告删除及运行中反馈变化必须使无效发布失败。反馈变化失效依赖画像，恢复结论不静默重新启用画像；操作不调用 Provider。

### A1 长篇分析读取

原文单元只读取所需章节/片段，汇总优先使用已验证产物。保持冻结清单、正文哈希、业务 owner 和提交时来源校验；不跨任务缓存私人正文，网络调用不持有数据库事务。源变化、取消、暂停和失去 owner 阻止发送或发布。

### A2 偏好来源与心跳

revision 覆盖正文/系列关系、报告身份与状态、明确评价及逐条纠错。稳定来源心跳不读取完整报告，预览和发布仍做完整验证；不能用宽松 TTL 接受旧输入，也不能把已读/收藏当作喜欢。

### S1 同步与传统统计

系列通过完整章节 ID 识别同数量换章，截断目录不标成完整。收藏正文回扫按账号/公开私密范围保存游标，并遵守现有页数和间隔。重算以当前归档为准，取消/失败保留旧结果，删除归档保留用户明确评价。推荐部分失败必须记录“部分完成”。

### W1 写作检索与后续维护

ai-writing 在短事务读取 revision、事务外计算 embedding、短事务核对版本后发布，倒序响应不能覆盖新索引。本次不把写作功能引入 main。继续按职责维护大模块，统一任务元数据时保留名称、优先级、默认参数和 API，不新增 Redis/Celery/Kubernetes。
