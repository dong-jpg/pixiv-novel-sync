# 修复与优化实施计划

更新：2026-11-19。这是唯一持续维护的开发计划；当前能力和验证边界见 [项目现状](STATUS.md)。完成项在本表更新，不再生成独立审计、整改、部署或完成报告。历史内容由 Git 保存。

## 目标与执行原则

1. 补齐已确认的使用缺口，优先解决错误结果、来源失效、并发和资源保留问题。
2. 优化长篇、大库和空闲运行开销；用读取次数、事务长度和正确性测试衡量，不预设加速倍数。
3. 将 Pixiv 任务逐步接入远程执行，VPS 始终保存唯一书库和业务状态；不能以两个试点任务代替全部业务完成。
4. 只保留 main 与 ai-writing。共享代码先进入 main，再通过 merge 进入 ai-writing；写作专属实现只在 ai-writing。
5. 文档只维护安装与使用、当前契约、开发设计、实施计划和当前状态。示例代码、测试输出、截图及旧执行清单不作为需求来源。

每个任务必须同时交付实现、对应现行文档和能覆盖风险的验证。代码完成、自动验证、生产启用与真实模型效果分别判断。普通代码开发不自动触发付费调用、生产迁移或云实例启动。

## 第一批：D1、X1、A1、R1

### D1 文档收敛

- 全部删除 `docs/archive/` 的历史报告与已过期副本；删除旧执行记录、生成截图和验证 JSON。
- 将仍有效的模型调用、作品分析、远程协议约束合并为稳定名称的设计文档；删除已执行的逐任务代码清单，保留可复用验证脚本到 `scripts/`。
- 统一需求只定义目标与边界；用户指南只写当前可操作流程；STATUS 只记当前能力、测试和待办。
- 更新 README、CLAUDE、索引、API 契约、页面清单及写作专属文档，纠正本机 CSRF、旧 OUT 决策和全云执行等错误描述。
- 检查 Markdown 本地资源、源码/测试中的文档路径以及两分支专属链接。私人未跟踪草稿不纳入清理。

验收：仓库不再携带历史报告/执行附件；活跃文档无断链；当前接口与文档契约测试通过；main 文档不引导用户打开不存在的写作页面。

### X1 逐条结论纠错

数据范围：只修改某一份已发布作品报告中的某一条结论的可信标记，不修改模型原文、不修改正文，也不替用户推断喜好。

实现：

1. 以报告身份和稳定结论标识持久化标记，支持“标记不可靠”和“恢复使用”；不能仅按页面序号关联另一份报告。
2. 接口校验报告存在性、结论归属、状态和版本；使用现有认证、CSRF、严格输入与事务。
3. 报告页面显示可信状态及操作反馈，处理重试、迟到响应、冲突和删除。
4. 画像来源投影排除不可靠结论；反馈变化必须改变来源版本，使旧预览、运行中的总结和旧画像不能继续当作当前有效来源。
5. 推荐仅使用当前有效且显式启用的画像；恢复结论也需要重新预览/总结，不静默复活旧结果。

验收：跨报告 ID 误用、伪造结论、过期版本、标记/恢复/重试、报告删除、画像执行中反馈变更与推荐失效均有回归；页面可操作，API 返回与界面一致；操作本身不调用 Provider。

### A1 长篇分析读取

入口：`work_analysis/executor.py`、`manifest.py`，保持冻结清单、正文哈希、业务 owner 和提交时失效校验。

- 原文单元只取得实际需要的章节/片段；汇总阶段优先消费已验证产物。
- 不引入无界全文缓存，不跨任务共享私人正文，不使用“只查缓存”代替来源校验。
- 读取与哈希校验在有界事务内完成；模型网络调用不持有数据库读/写事务。
- 源变化、取消、暂停、失去 owner 后仍必须阻止发送或发布。

验收：多章节、多单元合成任务用实际正文读取次数/字节规模证明减少重复 I/O；同长度改文、保存同 hash、源删除、系列关系变化、汇总中变化及恢复路径保持原语义。

当前合成回归：六章节、七单元，执行器和检查点分别读取 6 行 / 31500 字节，合计 63000 字节；原路径对每单元两次整源读取为 84 行 / 441000 字节。此测量是 SQLite 返回到 Python 的正文载荷，减少 85.7%，不代表物理磁盘读取或整体调用耗时同比下降。汇总阶段正文读取为零。

### R1 远程清理调度

采用 VPS 独立维护任务，调用现有 `pixiv-remote gc`。它不依赖 worker 在线，也不启动云机。

- systemd oneshot + timer，显式确认控制目录；示例默认不自动安装或启用。
- 延续 24 小时终态文件、14 天元数据和孤儿文件最小保留时间，保护活动任务/上传引用和当前 epoch 凭据墓碑。
- 维护命令失败要非零退出；中途退出可重入，路径错误/符号链接必须拒绝。
- 文档说明安装、启停、立即运行、日志核对及与原 Web/controller 服务的权限关系。

验收：时间边界、活动数据保留、重复执行、删除中断恢复和 unit 配置通过测试；不得把“已提供 timer”写成“生产已启用 timer”。

## 第二批：A2、S1、W1

### A2 偏好来源与心跳

先测量不同报告/评价数量下的查询次数、读取量和心跳耗时。引入轻量来源 revision 时必须覆盖：正文/系列成员变化、报告发布/删除/过期、读后评价、逐条纠错及有效范围变更。预览仍冻结完整来源清单，发送前/发布前以 revision 与必要的精确校验拒绝旧结果。

验收：稳定来源时心跳不读取全部报告 JSON；任一来源变更都能使运行中任务或旧画像失效；不能用宽松 TTL 接受旧输入。进行中只显示当前输入版本，不能把喜欢/已读关系互相替代。

### S1 同步与传统统计语义

1. 订阅系列不能只凭章节数量相同判定内容不变。当前整部跳过要求首页完整目录、无重复 ID 且各章节归档/附件可用；否则在已有分页上限内逐章处理，异常续页标记不完整。多页系列会比旧的错误跳过增加目录请求，仍受原页数限制；远端重排和同 ID 改文的周期回扫尚未实现。
2. 传统词频画像建立版本化重算入口，明确“统计当前归档内容”与“保留历史阅读喜好”的差别。归档删除不自动抹去用户明确评价。
3. 收藏连续完整页提前停止必须配合周期回扫，防止永久遗漏较早收藏的修改、取消或重新出现；先定义水位与范围再优化请求。

验收：同数换章、重排、分页重试、私密/公开范围、限流中断、重跑不重复计数；请求次数不超过配置预算且不增加 Pixiv 请求频率。

### W1 写作检索事务

先短事务读取章节内容与 revision，退出事务后计算 embedding，再短写事务核对 revision/模型身份并发布向量。发生倒序返回时丢弃旧计算，失败保留旧索引，禁止无界自动重试导致额外费用。

验收：网络等待期间其他业务写入可以完成；新版本先返回、旧版本后返回时只保留新索引；模型切换、章节删除、失败与取消均安全。仅在 ai-writing 实施，主分支保持写作路由不可用。

## 第三批：完整远程执行 R2–R6

### R2 单本抓取最小闭环

先定义版本化 task kind、严格任务 DTO、结果大小/格式与错误类别，再接 worker 固定处理器。输入只能包含已授权的作品身份和最小任务参数，不能是任意代码、URL、SQL 或文件路径。

VPS 校验 input digest、attempt/fence、账号/作品范围和结果 schema 后，复用本地归档事务写入正文、元信息、附件和索引；产物接收必须幂等。worker 不访问书库 SQLite，不把云端数据库覆盖回 VPS。取消后迟到结果不能落库。

### R3 账户一致性与凭据

- 将当前本地任务与远程任务纳入同一账号/范围锁，互斥期由有界租约管理，不能本地云端同时遍历同一收藏。
- 共用请求限额和退避状态；失联不能让两端各自获得完整请求额度。
- 使用短期、按任务/账号范围限制的凭据交付；worker 日志、错误、下载结果、持久队列及浏览器不得出现密钥。
- 远端未知执行状态不自动重新登录/重发有副作用请求；任务取消、租约过期和恢复分别验证。

R2/R3 验收：fake Pixiv 与本地 HTTP 模拟完成抓取→传输→落库；断网、上传重复、任务取消、账号锁竞争、限流和凭据轮换通过后，才进入真实账号的小规模验收。

### R4 同步任务逐种接入

依次接入单篇获取、订阅系列、作者备份、关注更新、收藏同步、状态检查。每种任务都复用现有水位、取消、不完整状态、删除判定与救援目录更新，不以一个泛化 shell 任务替代业务协议。

每种任务独立验收：本地与远程在相同合成输入下归档/水位一致；重启不漏不重；部分失败的日志与 CLI 状态一致；网络故障可恢复且不重复提交已确认结果。全部通过后才标记“Pixiv 同步完整支持远程执行”。

### R5 推荐、分析和调度

推荐读取最小候选投影；分析仅发送经明确确认的冻结正文/预算，不把全部书库搬到 worker。远程任务继续遵守父级预算、付费请求预留、证据验证及检查点，不因重试重算已确认付费单元。

任务执行位置配置为本地或远程，由 VPS 单一调度器决定；保持旧定时任务身份/时区/优先级及水位，禁用另一端重复 cron。远程不可用时不能静默扩大预算或改执行位置。

### R6 签到与其他副作用

先接现有单站只读状态适配器；真正签到另设固定操作、日期/账号幂等键、提交/确认/未知结果台账。请求超时视为结果未知，先查询状态，不盲目重做。与当前 Pixiv 书库需求分开验收，不提供任意站点任务执行。

## 第四批：测量与维护 A3、M1

- 单元用量读取改成分组查询前，测量真实 N+1；图片优先可见区域，但保留油猴 SPA 兼容和缓存边界。
- 对空闲 claim 的磁盘探针、文件账本扫描先建立计数基线；轻量 gate 只能减少无效工作，领取事务仍做最终容量/租约检查。
- 根据持续修改热点拆分 `webapp.py`、`sync_engine.py` 和大写作服务。每次拆一个职责，避免仅搬文件却增加跳转层级。
- 任务元数据统一注册时保留名称、优先级、默认参数和已有 API，禁止一次更换整个队列系统。
- 不引入 Redis/Celery/Kubernetes 或平行 Agent 框架；保留单进程 Web 约束。

全量测试在本阶段代码稳定后运行，不将同一测试的多次运行相加。Windows 跳过不能替代 Linux；合成样本不能代表模型质量。失败先修复再重跑受影响范围，最终提交源码必须与验证源码一致。

每批代码完成后更新 STATUS、相关指南和本计划，提交 main，再合并并验证 ai-writing，最后同时推送。发布前确认只有两条长期分支；原有私人数据、未跟踪草稿和 stash 保留。生产启用单独执行备份和回退步骤。
