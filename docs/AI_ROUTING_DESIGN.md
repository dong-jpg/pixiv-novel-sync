# AI 目录、设置与统一调用设计

本文维护当前共享 AI 契约，合并原模型目录/模型池规格和统一调用设计。操作流程见 [模型路由指南](MODEL_ROUTING_GUIDE.md)，HTTP 字段见 [API 契约](frontend-api-contract.md)，开发顺序见 [实施计划](IMPLEMENTATION_PLAN.md)。

## 职责与兼容

- Provider、目录模型、路由组和 Agent 使用稳定数据库 ID。支持多个同协议 Provider；模型同名不代表同一身份。
- 当前协议是 OpenAI-compatible Chat Completions、Anthropic Messages；xAI 复用 Chat 适配。能力标签不等于已经实现工具循环、视觉输入或原生严格 JSON 输出。
- `AIWritingService` 是历史门面名称。main 使用它管理 AI、清洗关键词，并通过统一调用支持作品分析与个人画像；写作服务只在 ai-writing。
- 业务生成必须经过 `ModelRouter`。只有 Router、Provider 实现和显式连接测试可直接调用 `stream_generate`。
- 不新增外部网关、Agent 框架、必装 tokenizer 或平行任务系统。Web 保持单进程。

## Provider 与模型目录

连接测试、模型探测、目录同步是不同操作。零网络配置检查不能证明远端凭据有效；探测候选不自动写入目录；目录同步不自动启用新模型或改变用户绑定。

模型 key 是上游不透明标识，拒绝控制字符但不大小写折叠或 NFC 改写。显示名、能力和白名单 metadata 可规范化。同步仅维护 `discovered_*`、可见性和最后发现时间，保留手动字段与 enabled 值；消失的被引用模型不能直接删除。

空目录必须显式确认，确认绑定 operation、generation 和结果摘要。已失效、取消或被后续同步替代的确认不能覆盖新目录。一次同步最多 100 页、5000 个模型、20 MiB，总时限 10 分钟，单页最多 4 MiB。

所有出站使用现有 SSRF、DNS/IP 固定、Host/SNI、TLS 与禁止重定向策略。Key 加密存储、只写返回；存量 Key 借用只能通过已认证的受控 Provider 身份，不允许客户端引用任意密文。Provider 配置变化使旧同步/调用计划失效。

## 路由组与绑定

路由组是有序池，按成员顺序后接后备池；拒绝循环，最多 8 个池节点。单池最多 64 个成员，候选展开去重最多 64 个；每次调用最终最多尝试 16 个候选、32 次物理请求，总时限 30 分钟。

成员整体替换、删除、禁用和清空必须在事务中验证所有引用。写操作携带 `expected_version`，冲突返回 409；不能用最后写入覆盖并发编辑。固定绑定与池绑定互斥；既有 Agent 迁移为 fixed，保留原模型、Prompt、参数和启用状态。固定 Agent 不自动跨 Provider 切换。

## 完整文本预检与执行

v2 统一请求携带完整 system/user/assistant 文本。预检逐候选计算 `input_tokens + message_overhead + safety_margin + output_reserve`，分别与该候选有效窗口比较；不能用不同模型的最大输入与最小窗口拼成一个预算。

预检最多 256 条消息、16 MiB，不联网、不解密 Key、不创建 job。缺未知窗口必须明确说明，不填零；token 估算不声称等于厂商计费。输出预留、Agent/Provider/模型限制分别展示，不自动提升用户配置。

执行冻结候选链和相关版本，候选临时不可用时按冻结计划解释。首个正文 delta 之前可有序故障转移；正文已经输出后失败为 partial，不自动换模型拼接。取消、断连或 `GeneratorExit` 不触发后备调用。

v1 旧写作快照的哈希、裁剪和剩余候选语义继续保持。main 的通用 continue 返回 409，不创建任务；作品分析通过自己的 `/resume` 和检查点恢复。ai-writing 的旧写作继续由服务端按具体任务判断，不能把写作继续应用到作品/画像调用。

## 请求、用量和隐私

每次物理发送前，在同一事务分配网络序号并记录 pending/未知用量。Provider 的内部重试也计数；无请求的 ordinal=0 关联不冒充发送。已报告量、部分已知量、未知量分开聚合，不把缺失 usage 算作免费或零 token。

通用统一调用使用 `metadata_only`，不保存完整 Prompt/正文/响应供重放。关键词清洗仅保留有限词和标签的内部兼容数据；作品与画像保存独立、私有、有界业务产物和短证据，不进入普通日志或公开救援数据。

job/attempt 保留 owner、lease、候选/配置身份、结果状态、脱敏错误和时间。owner/CAS 检查覆盖心跳、请求预留、终态与清理；租约有效的其他任务不能被清理请求误杀。错误体、SSE 与诊断都不能包含凭据或完整敏感输入。

作品父绑定与画像父绑定互斥，由服务端构造。父预算预留和网络序号同事务完成，发送结果未知保守计账；重启不能清空累计预算。业务产物验证失败与网络传输成功分别记录。

## 设置页面与回归边界

设置页只提交用户实际修改的字段，保留合法 0/false；失效绑定仍可见并说明原因。选择器搜索、开关弹层和目录刷新不写配置。发生 CAS 冲突保留编辑草稿，迟到响应不能覆盖当前 Provider、Agent 或模型选择。

当前不实现跨任务健康冷却、权重轮询、成本排序、后台自动目录刷新、金额硬预算。新增协议/能力必须同时具有传输实现、业务消费者、预检约束和测试，不能只增加能力标签。

修改此模块至少覆盖：目录空确认与并发同步、池引用/CAS、完整输入容量、首正文边界、取消、物理请求计数、未知用量、配置变化、资源释放、隐私和旧写作兼容。相关套件为 `test_ai_model_*`、`test_ai_invocation_*`、`test_ai_generation_deadlines.py` 及调用业务套件。
