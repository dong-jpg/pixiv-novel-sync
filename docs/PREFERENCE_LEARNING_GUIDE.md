# 偏好学习使用指南

偏好学习把已验证的作品报告与你明确表达的读后喜恶关联起来，生成可追溯的个人偏好 / XP 画像，再用于后续搜索与推荐。页面位于 `/dashboard/preferences?view=learning`；偏好页顶部可以切换“偏好与推荐”“单作品分析”“偏好学习”。

本文描述当前代码的使用方式。生产是否已更新、测试在哪些环境完成，以 [项目现状](STATUS.md) 为准；合成测试和本地预览不代表真实 Provider、账单或手机设备已验收。

## 先完成一部作品的报告和评价

1. 在已归档的小说或系列详情点击“分析作品”，按单作品流程选择 Agent、核对正文范围和章序、填写有限预算，预览后明确开始。作品报告以当前归档为准，缺章或连载继续显示，不自动补齐。
2. 阅读后，在作品详情点击“评价与修改”，读取当前评价，再选择“喜欢”“不喜欢”或“中立”，可填写最多 500 字原因。保存只写本地评价，不调用模型。需要取消这条信号时使用“撤回评价”。
3. 也可在“偏好学习”里的评价区域输入作品类型和 ID，读取后修改。系列评价优先于其章节评价，避免重复计算同一系列。

作品被收藏、追更、归档或读完，不自动证明你喜欢它。作品里出现某个情节，也不直接说明这是你的偏好。AI 画像保留这种不确定性，并给出对应作品依据。

顶部“有报告和评价”表示可用于画像的来源数；“已评价但缺有效报告”表示尚需分析或更新的作品。成功报告还必须有完整的本次输入覆盖、完成汇总、没有过期或删除，才可纳入画像。

### 纠正某条分析结论

打开成功报告，在相应结论旁选择“标记不可靠”。原结论和证据仍可查看，但该结论不再用于后续个人画像。确认原判断可用时选择恢复；这只是恢复使用资格，不表示用户担保模型判断真实。操作只写本地状态，不调用模型、不修改小说正文。

标记和恢复都会使依赖该报告的旧画像失效并取消启用。需要重新预览、生成并显式启用画像，不能继续使用此前的预览或让恢复操作自动复活旧画像。作品级喜欢/不喜欢与逐条结论反馈是两种独立信号。

过期、归档范围已更新或已删除的报告不能继续纠错，请先为当前来源生成报告。遇到版本冲突刷新后核对状态；网络结果未知时先读取当前报告，不盲目重复提交新版本。

## 预览并生成 AI 偏好画像

在“AI 偏好 / XP 画像”选择已配置的 Agent，填写输出预留以及请求数、计划 token、活跃秒上限。三个支出预算初始为空；表单不会替你授权付费。

点击“预览画像依据与预算”后，检查以下内容：

- 本次可用来源作品数和缺少报告数。
- 可能接收报告摘要、短证据及评价的 Provider / 模型。
- 当前预检所需的最低预留与自己填写的累计预算。
- 缺依据、容量不足、预算不足等提示。

预览只读取本地配置和依据，不发起模型请求。确认外发与累计预算后点击“生成 AI 画像”；切换 Agent、修改输出或预算后必须重新预览、重新确认。最低预留只说明已知的一次调用需求，重试等实际行为仍受累计上限控制。

生成使用共享后台任务槽，繁忙时排队。页面可以刷新查看；queued / running 时可以取消，但正在返回的网络调用可能需要等待真实退出。不要把“已点击取消”理解成远端已停止计费。

## 核对画像并用于推荐

从画像记录选中一个版本，点击“读取画像结果”，再展开内容。结果分为摘要、偏好 / 回避 / 混合 / 中立维度、反例及不确定性。依据作品和短证据分别折叠；可进入原作品报告，或到阅读页核对同版本原文。证据的版本已变化时，旧偏移不会高亮到新正文。

核对后勾选“将这版画像用于后续搜索词、排序和推荐理由”，点击“启用到推荐”。只允许启用成功且没有过期的版本；启用新版后旧版不再是当前推荐依据。第一次启用时，即使此前没生成本地统计画像，也会建立所需的基础默认画像。

回到“偏好与推荐”运行推书。每次推书重新生成搜索计划，使用最新有效信号；明确喜好参与搜索和排序，明确不喜欢参与负向打分。推荐卡片显示学习依据，有 AI 画像引用时可以返回对应版本核对。推荐项上的“感兴趣 / 不感兴趣”保留原反馈功能；读后喜恶请在作品评价里表达。

修改评价、删除来源或更新正文后，旧画像可能显示已过期或依据失效。它不会继续作为可启用的新依据；需要按新报告和评价重新预览生成。失效处理会清理不再支持的敏感产物，因此并非所有旧结果都能永久保留为历史档案。

## 批量分析当前归档

在“全库与新同步作品分析”选择“手动启动一个批次”。选择范围：

| 范围 | 行为 |
| --- | --- |
| 全部归档 | 扫描现有归档，按系列归并；已有同源、同配置的有效报告复用 |
| 仅新增 / 正文更新 | 处理本功能开始跟踪之后实际新增或正文变化的归档；同 hash 元数据刷新不触发 |

分别填写每部作品的预算与本批累计总预算，以及作品总上限。总预算的每一项至少容纳一部作品的预算。预览后核对候选数量 / 样本 / 服务目标，并确认当前归档范围、现有章序、外发和总预算，再启动。

每个新付费作品先占用完整的单作品预算，因此“已分配”不是实际账单；作品中断或少用额度也不自动退回这份授权。已有同版本任务不会因为再次扫库就创建第二个付费任务，原本失败的任务同样需要明确处理。

批次详情列出发现 / 纳入 / 跳过数量，每个作品显示真实分析状态，点击“查看作品分析”可看具体原因和报告。**“批次发现已结束”只表示发现环节结束，不表示每份报告成功。** 失败、缺正文、过期或未完成都应按作品分别核对。

暂停 / 取消会停止本批后续工作并控制相关进行中的子任务。恢复 paused / cancelled 的批次沿用原累计预算，只恢复由该批次停止且仍有效的任务；已失败或验证失败的作品不会被自动重付费。批次 failed 时应检查原因，再决定是否建立新批次；复用记录仍避免同源重复付费。

## 开启新同步后的自动分析

选择“持续自动发现”，设置范围、Agent、单作品预算、累计总预算、作品总上限和发现间隔。再次预览后，“保存持续自动分析授权”才会开启后台自动工作。

自动模式下“仅新增 / 正文更新”的起点是首次开启时；只纳入之后新增或正文改变的归档。关闭、恢复、增加预算都保留这个起点。此前已有归档可单独运行手动全库批次。

持续策略的总预算和作品数是**跨批次累计上限**，不会每隔一轮重新赠送额度，也不会关闭再开就清零。达到任一限额会停止继续准入；想继续时点击“载入当前授权以调整”，增加有限上限、重新预览并确认。不能将新上限降到已分配额度之下。

“停止后续自动分析”会停止发现并暂停尚在执行的自动批次；当前调用须等待退出，已进入最终保存的结果仍可完成。它不清除已有报告，也不退款或重置累计计数。若之后恢复旧自动批次，策略须先启用且配置仍匹配。

单作品页的预算增加也不能绕过批次或自动策略总上限：增加额会同时计入父级分配，超出总授权则拒绝。持续总额可重新预览增额；手动单批次的授权在创建时确定，后续先检查其剩余额度。

## 中断、未知结果与删除

| 情况 | 操作 |
| --- | --- |
| 预览变旧或版本冲突 | 刷新数据，重新预览确认；不直接重复旧控制 |
| 创建提交结果未知 | 使用“重试同一创建”，保留同一请求与幂等键，不另建一份任务 |
| 暂停 / 启用 / 保存评价结果未知 | 先核对当前状态；版本未变时页面才允许重试同一操作 |
| 操作成功但刷新失败 | 只重试读取，不重复提交 |
| 服务重启且有未完成批次 | 批次暂停，相关自动策略停止；核对状态后明确启用 / 恢复，不自动重发可能已付费的请求 |
| AI 画像生成因进程中断失败 | 没有旧任务 continue；查看原因后重新预览、明确创建新生成 |
| 画像已旧版化 | 更新对应作品报告 / 评价，生成并启用新版本 |

原请求、画像、同意和评价不会写入浏览器 localStorage / sessionStorage。页面重载后不能假定上次提交失败；先核对记录。应用使用原有 Dashboard 登录和 CSRF，阅读评价只在主动展开时读取。

画像和单作品分析分别提供删除：删除前撤销运行权，并清理对应敏感结果和可恢复来源；旧 worker 或迟到响应不能重新写回。删除作品来源还会使依赖它的画像失效。应用层删除不承诺备份、SQLite WAL 或介质立即物理清除。

接口字段、上限与状态码见 [前端 API 契约](frontend-api-contract.md#preference-learning-apis)。所有自动化仍依赖现有服务调度和共享执行槽，不需要浏览器一直开着，也不使用旧 AI job continue。
