## 分支与运行边界

| 分支 | 范围 | 维护方式 |
| --- | --- | --- |
| main | 同步、归档、救援、阅读、推荐、作品分析、偏好学习、远程执行基础与共享 AI | 共享修复先进入 main |
| ai-writing | main 全部功能，加创作项目、章节、向导、蒸馏、检索与润色 | merge main，写作不反向合入 main |

本地与 GitHub 仅维护上述两条分支。既有写作数据表在 main 迁移时保留，分支切换不代表删除数据。

代码交付与实际部署分开。最新留存生产版本信息为 2026-11-13 的 `4b8133e`，不是本轮重新核验的在线 HEAD。2026-11-20 已按用户授权测试线上三个 Provider 的短生成及一次云诊断；未部署本轮新代码，不能据此确认新增业务协议已经在线启用。

## 远程执行任务清单

下表区分 worker 接手的步骤与 VPS 保留的业务。业务协议已接线，不代表每种任务都在目标环境完成了验收。

| 任务 | 可交给云机的部分 | 留在 VPS 或仍需验收 |
| --- | --- | --- |
| 收藏同步（公开/私密）、关注列表、关注作者作品、作者备份 | 固定收藏、关注、作者作品、详情和单篇正文调用 | 分页调度、水位和归档在 VPS；支持 `max_bookmark_id`，旧式非零 `offset` 改为固定收藏 endpoint 透传，已覆盖真实 SDK 边界回归；远端是否继续接受旧分页仍需真实输入验证 |
| 追更、用户/小说/系列状态、待删除检测、快速同步 | 固定追更列表、详情、系列目录；快速同步复用这些调用 | 判断删除、调度、取消和写库在 VPS |
| 单本小说、推荐搜索 | `pixiv.novel.v1` 获取单篇详情与正文；`pixiv.api.v1` 搜索候选 | 图片/附件、索引、推荐排序及来源留在 VPS |
| 作品分析、偏好画像、AI 写作文本 | 走统一路由及预算检查的文本生成可接 `ai.text.v1`；写作只在 ai-writing | 检查点、预算、统计、结果发布及写作检索 embedding 在 VPS；模型设置页的“测试连接”缺少远程预算入口，需在本地执行模式测试 |
| 连接诊断、单本 EPUB | 手动提交 `diagnostic.v1`、`epub.single.v1` | 既有线上诊断成功；整库、批量 ZIP 和常规下载并未迁到 worker |
| 单站签到 | 固定状态查询和一次提交，未知结果只查询 | 需独立安装兼容依赖与已授权会话；真实站点提交待验 |

Pixiv 通过 `sync.pixiv_execution=remote` 启用，AI 文本通过 `PIXIV_REMOTE_AI_EXECUTION=remote` 单独启用。默认上游转发由 VPS 发起；可选 HTTPS CONNECT 只改变远程 Pixiv/模型请求的公网出口。OAuth 登录和附件下载仍在 VPS。独立 CLI 的远程 Pixiv 任务依赖在线 Web worker API，远程 AI 应从 Web 业务入口执行。配置、升级及回退见[远程指南](REMOTE_EXECUTION.md)。

## 代码审查与修复

本轮覆盖 main 的 128 个 Python 源文件及模板、JS、油猴，核对调用关系、同步/存储/认证/任务/AI/分析/远程边界，并对 ai-writing 独有实现和共享继承运行回归。工作区原有修复纳入核查；测试通过不代表全部输入和竞态已证明无缺陷。

| 问题 | 处理与证据 |
| --- | --- |
| 脏 `archive_dir` 指向书库根，删除单部作品可能影响整库 | 拒绝任一根及其祖先，包括相互嵌套的存储根；删除/暂存回归验证其他备份保留 |
| 系列章数相同直接跳过，漏掉同数量换章或丢失附件 | 快速跳过核对完整章节 ID 和磁盘文件；分页仍受原上限约束，异常续页标记不完整，正常逐章跳过计数正确累计 |
| 下载流和最后替换前不响应取消 | 每块下载及替换前探询取消，保留旧文件并清理临时文件 |
| 图片代理沿用压缩前后的错误 Content-Length；非法端口触发 500 | 按实际返回字节计算长度；非法 URL 返回 400，不发上游请求 |
| 500 字评价的 UTF-8/JSON 上限偏小 | 按最坏 JSON 编码长度校验，500 个 emoji 或控制字符可正常处理 |
| 小说库卡片显示“0 字”，实际正文非空 | 收藏/最近小说 SQL 补齐 `text_length` 投影；线上零网络分析预览确认正文存在，列表数据回归通过 |
| 作品单元详情/报告 N+1 读取用量账本 | 七单元实测：私有详情、报告、单元分页各 1 次查询；保留未知用量与真实零值区别 |
| 页面依赖外部 Vue CDN，受阻后一直隐藏 | 固定版本 Vue 与许可随 wheel 提供，保留 SRI 和版本缓存，移到页面内容之后加载；未挂载时显示提示 |
| 固定栏模糊、滚动重复布局读取与同步存储写入 | 常驻栏改实色，每次滚动只读取一次位置，像素缓存按滚动组/300ms/pagehide 保存；CAS 意图及时采样，存储被禁仍能阅读 |
| 油猴重复快速扫描、邻卡误判和迟到响应 | 观察器合并 DOM 更新，保留 3 秒兜底，离开释放；限定卡片边界，写入前复核仍失效且作品身份一致 |
| 无调用旧路径 | 移除 `delete_reading_progress`、`get_all_series_ids`、`_has_any_running_web_job` 和关键词清洗中重复 `_forward_route`；保留 Flask/HTTP 库回调和 ai-writing 实际使用的共享接口 |

前阶段 X1/A1/R1/W1 继续有效。六章节合成分析正文载荷由原路径 441000 字节减到 63000 字节，汇总不重复读取正文；这是 Python 接收的正文规模，不表示模型总耗时同比下降。阅读回归中 100 次同百分比滚动只写一次旧像素缓存，离页再保存最终位置。

偏好心跳已改为轻量来源 revision（A2），覆盖明确评价、报告身份/状态/单调 revision、纠错及来源关系；运行中不重复读取整份报告/正文，预览和发布保留完整验证。合成 1/25/100 来源心跳约 0.35/0.72/1.42ms，报告正文读取均为零，不能代表真实大库延迟。S1 已保存完整系列观测顺序、按账号与公开/私密范围续跑收藏回扫，默认七天检查旧正文；当前书库统计可原子重算，取消/失败保留旧结果，删除归档保留用户明确评价。

单进程 Flask + SQLite 与两类不同任务生命周期仍适合当前用途。`webapp.py`、`sync_engine.py`、模型 Router 和写作服务的大文件，以及多处任务类型/标签注册增加维护成本，可按职责逐步拆分；不需要为此引入另一套队列或 Agent 框架。远程 lease/fence/幂等、分析预算和来源失效校验用于防止迟到发布及重复付费，不能当作死代码删除。
