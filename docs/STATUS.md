**代码交付不等于实际部署。** 本轮没有登录生产主机、更新服务、唤醒云实例或调用付费模型。最新留存生产代码记录是 2026-11-13 `4b8133e`；11-16 早先的公开健康探测不证明生产 HEAD 未变化。作品分析、个人画像、全库分析及本轮修复仍需生产发布。

## 尚未完成

1. **完整远程执行**：接入固定 Pixiv 抓取任务、账户 / 范围互斥、共享限流、最小凭据和 VPS 结果收口；之后才可迁移收藏、关注、追更等业务。签到副作用台账与业务 cron 也未迁移。见 [远程执行](REMOTE_EXECUTION.md) 与 [后续阶段边界](superpowers/specs/2026-11-12-remote-next-phase-notes.md)。
2. **生产发布与外部验收**：本轮两分支应用、数据库迁移与回退、真实 Provider 长输入 / 账单 / 取消、手机 0.12.3、完整云机冷启动 / 强制中断 / 冷却和独立备份仍需分别验收。
3. **传统统计画像版本化**：旧词频累加器不会随已分析正文变化或历史删除自动扣减，需要显式重算；新作品报告和个人 AI 画像有来源失效检查。后续改动需定义删除归档是否应抹去历史兴趣。
4. **同步与大库优化**：按章节数量相等跳整部系列不能识别同数量换章；收藏连续完整页提前停止 / 每日回扫尚未实现。分块分析重复读取正文、证据重复验证及图片首屏开销仍需按实际数据测量。
5. **维护债务**：webapp.py、sync_engine.py 和若干模板较大，任务注册分散；可按变更热点逐步整理。部署脚本尚不提供数据库自动回滚或跨主机事务发布。
6. **报告逐条纠错**：实现原设想中按结论标记不可靠，并定义其对画像和推荐依据的失效规则；在实现前不能把作品报告当成已人工确认的标签。
7. **远程垃圾回收调度**：现有 GC 只有明确的 CLI 入口；24 小时产物 / 14 天元数据是执行 GC 时的保留规则。尚未提供自动 timer，长期不运行 GC 可能耗尽 1 GiB 配额，见远程指南维护命令。

## 保留的边界

- 救援目录继续全量事务重建；批量查询优化不改变收录资格。
- main 不引入写作功能；共享名称 AIWritingService 是历史兼容门面。
- 框架回调、兼容存储方法、续跑基础设施及尚未接线的远程适配器不能仅凭静态“零调用”删除。
- 不把单次审计或测试全绿解释成所有输入、竞态和外部服务均已证明无 bug。
