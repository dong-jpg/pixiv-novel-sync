## 1. 已选择的方向

VPS 是长期在线的业务主服务和数据权威；InstaBox 是可随时中断、可重建的按需执行节点。

| 所在位置 | 保留职责 | 不承担的职责 |
|---|---|---|
| VPS | 固定域名、HTTPS、登录、阅读页面/API、主数据库、归档、任务计划、结果接收、实例生命周期控制 | 不把实例运行状态当成任务成功，不将业务数据库交给云端直接写 |
| InstaBox | 领取允许的任务、执行计算或经授权的抓取、回传进度和结果 | 不运行第二套书库、业务主库、独立业务 cron 或常驻对外管理面板 |
| 浏览器 | 展示、交互及离线缓存 | 不作为跨设备阅读进度的唯一来源 |

**阅读时段不再是云实例的保活时段。** 21:00 至次日 04:00 直接访问 VPS，甚至全天都可访问；只有真实任务需求才启动 InstaBox。不建立晚间七小时的固定保活循环。

云端资源较多不代表所有任务值得搬迁。Pixiv 同步受网络、站点限流和认证影响，远程 API 调用也不一定吃本机算力；是否迁移由实际任务耗时、VPS 资源占用及传输量决定，不承诺仅因换机器就加速。

### 1.1 不采用的路线

- 不把整套书库迁至云端后让阅读依赖免费实例的唤醒和冷却。
- 不在两边各运行可写数据库再双向合并，不用文件同步工具同步活跃 SQLite/WAL。
- 不把 SQLite 放到跨主机共享目录，也不把任意 SQL 调用包装成远程接口。
- 不为一期引入 Kubernetes、Redis、Celery、PostgreSQL 或对象存储服务。继续使用现有 Python 3.10+、Flask、SQLite 和文件归档；是否扩展独立评估。
- 不复制或直接执行第三方保活脚本，不采用绕过平台时限、轮换实例规避冷却的策略。

## 2. 当前实现决定的约束

以下是本地代码事实，不代表生产环境已经验证。

| 当前事实 | 对设计的约束 |
|---|---|
| `cli.py` 启动同一 Flask 应用；`webapp.py` 创建自动调度器 | 云端必须有专用 worker 入口，不启动另一套完整 Web 应用 |
| `storage/connection.py` 使用本地 SQLite WAL；归档同时依赖磁盘文件 | 主库和归档仍在 VPS；云端只接收任务所需数据 |
| `jobs/manager.py` 的队列和单执行槽只在进程内 | 新增持久远程任务记录和原子领取，不能把当前内存队列当分布式队列 |
| `webapp.py` 启动时将遗留 running task_logs 标失败 | 远程任务必须按租约恢复，不能被本地启动清理误判失败 |
| `jobs/runner.py` 的 executor 返回后进入收尾 | “云端已接单”不能通过现有同步 executor 被记录为执行成功 |
| `web/managers.py` 重启恢复间隔任务时跳过 cron 任务 | 调度事件必须在 VPS 持久化，明确补跑规则；不能依赖云端开机后自动补 cron |
| `webapp.py` 的 `/api/health` 不打开数据库 | 该接口仅做存活检查，另设执行环境就绪条件 |
| `dashboard_novel_detail.html` 自动存本地进度，本地值优先 | 后续单独解决跨设备进度；固定域名或搬库不能自动完成这一点 |

现有本地同步运行通道默认保留。新增模块按生命周期、任务协调、worker、结果存储划分职责，不继续将全部逻辑塞进 `webapp.py`。

## 3. 数据和权限边界

### 3.1 唯一权威数据源

Pixiv 业务数据库、归档、收藏归属、同步水位、阅读进度和最终任务结果由 VPS 管理。云端只允许任务级输入快照、工作目录及可丢弃缓存，不能持有另一份供业务读写的主库。

任务输入使用明确类型与协议版本，不允许传入任意 shell 命令、SQL、Python 源码、回调地址或 VPS 文件路径。结果只能通过预定义的业务适配器提交，不能按 worker 提供的路径覆盖服务器文件。输入、暂存区和缓存有容量上限与清理策略，完成确认后可删除云端工作目录，不把有限云盘当成长期归档。

“收到结果”与“发布结果”分开：上传到 VPS 暂存区、校验身份和摘要、持久化文件，再提交引用文件的数据库记录；数据库发布成功后才报告成功。断电后允许存在可识别的未引用文件，但不能存在指向半写文件的成功记录。

分块输入/上传以 `run_id + attempt_id + chunk_id` 去重。同编号、同摘要返回原确认；同编号、不同摘要拒绝。接收区、输入快照版本和已发布业务版本分离，不能因为收到第一块就更改输入版本并使后续块自相冲突。

### 3.2 凭据和网络

- InstaBox 管理 API key 只留 VPS，绑定显式配置的目标机器；不遍历并操作账户所有实例。
- worker 主动通过 HTTPS 连接 VPS，无须给云实例开放入站管理端口；校验证书，不因连通性问题关闭 TLS 验证。
- worker 注册凭据独立于 Dashboard、救援及业务账号。执行权限绑定 worker、连接会话、任务和 attempt，可撤销，并在租约到期后失效。
- worker 只取得当前任务允许的数据，不取得整份 `.env`、AI 解密密钥、Flask 会话密钥或全库导出权限。
- 一期 EPUB 试点不需要 Pixiv/签到凭据。以后确需第三方凭据时，逐项目审查最小授权、刷新、缓存及清理；暂停实例不等于擦除磁盘秘密。
- 限制任务输入、日志、上传文件及解压总大小；拒绝路径穿越、符号链接、非预期归档成员及越权结果。下载仍走 VPS 原有登录和对象授权。
- 日志脱敏，不记录密钥、Cookie、正文或完整上游响应。任务可观测信息与敏感输入分开存储。

签到与 Pixiv 共享调度和状态展示，不共享业务账号或数据库表。未知签到项目的内部数据如何保存，必须审阅该项目后决定；不能先假定“只保存一个成功布尔值就够了”。

## 4. 单一调度来源和持久任务协议

### 4.1 调度事件和运行尝试分离

VPS 保留唯一的业务计划。按 `Asia/Shanghai` 解释用户日程，持久化 UTC 时间，并保留业务日和时区；重试不能把原本的签到日期悄悄改为当前日期。

定时事件以项目、任务类型、目标范围、计划版本、原定执行时间组成稳定业务键。重复轮询、VPS 重启或补跑不会创建同一事件的第二份任务。手动提交使用调用方可重用的幂等键；网络重发沿用原键。

一个业务事件对应一个 `run_id`，执行重试产生不同 `attempt_id`。持久记录至少包含输入摘要/版本、计划时间、最早执行时间、截止时间、执行目标、结果状态和失败原因。不是每次 HTTP 请求都生成一个新的业务事件。

一期仅手动提交诊断/导出试点，不改变生产业务 cron。接入具体定时任务时，同一任务只能选择 local 或 remote 一个路由；删除云端重复 cron，并将对应本地通道纳入统一互斥。未迁移任务继续本地执行。

### 4.2 原子领取与失效隔离

VPS 在短事务内原子领取任务，生成执行代号（控制器世代加本世代单调递增的 fencing token）、租约和 worker 身份绑定。心跳、结果接收和最终发布都核验任务状态、控制器世代、执行代号、有效租约及输入快照。数据库事务中不等待网络或执行文件传输，避免阻塞阅读请求。

一期默认每台实例一个执行槽。初始控制参数为心跳 30 秒、租约 180 秒；worker 在距最近一次确认续租超过 120 秒时停止开始新工作并进入停止/核对流程。租约是否有效以 VPS 时间为准，worker 用单调时钟估算自己的保守停止期限。

断线重连、进程冷启动或长暂停后，worker 必须重新握手并核实执行权限，不能凭旧内存或缓存继续。旧 attempt 结果不得更新当前任务；已持久化的相同成功提交可以查询确认，不要求它重做计算。

`task_logs` 是用户可见日志，不充当领取锁或队列本身。远程任务记录先成为权威状态，再映射到现有页面；VPS 重启只核对租约，不将全部远程运行任务直接改成失败。

### 4.3 失败分类

| 情况 | 行为 |
|---|---|
| 实例启动失败、冷却、尚未领取任务 | 保留待执行需求，按返回的可重试时间退避，超过业务截止时间明确过期 |
| 纯计算任务中断，输入快照仍在 | 使旧 attempt 失效后可以重新计算；一期自动重试最多两次 |
| 结果已提交但响应丢失 | 按业务键和结果摘要查询原确认，不重复发布 |
| worker 失联，外部副作用是否发生未知 | 标为待核实，先查询业务结果；无法核实则人工处理，不盲目重跑 |
| 输入版本与请求不符、权限错误、协议不兼容 | 拒绝执行或发布，保留诊断；不是不断重试的临时错误 |
| 取消任务 | 撤销后续执行/发布权限并等待协作式停止；不声称已撤销发生过的外部操作 |

**fencing 只能防止旧 worker 写入 VPS，不能阻止它在第三方网站完成签到。** 所以“旧租约失效”不等于“安全地在 VPS 重签”。具有未知副作用的任务不启用自动本机接替；只读或有明确幂等保证的操作另行制定策略。

## 5. InstaBox 生命周期

### 5.1 启动和就绪

持久需求出现后，由 VPS 的单个实例控制器执行状态查询、必要启动及运行监控。实例操作也持久化幂等键和 operation ID，超时后先核对已发操作，不无脑重复 start。

按实际状态选择启动/恢复动作，区分 paused、stopped、starting、resuming、running、error；不能把所有非 running 状态都当作可立即启动。以平台当前文档和返回值为准。

就绪必须依次满足：生命周期操作成功、runtime ready、worker 握手成功且协议/任务能力匹配、VPS 结果接收与存储可用。固定等 20 秒、看到 running 或收到 HTTP 202 都不是就绪判定。

服务在冷启动时能自动启动 worker；内存恢复只是优化，不是可靠性前提。业务进度确认以 VPS 持久记录为准。

### 5.2 保活、排空和暂停

只有有效任务、结果发布/核对或用户显式保留需求时才保活。任务到期或失败后必须释放不再有效的需求，避免一个坏任务无限撑住实例。

无需求后等待 5 分钟的空闲宽限，合并邻近任务，随后进入 draining：停止派发、确认结果落地、再次核对新需求与人工保留开关，才请求暂停。暂停失败必须可见，不得显示成已暂停。

控制器只自动管理被明确授权纳管的实例，且只自动暂停由自己激活、当前仍归自己管理的运行会话。发现实例已由用户手动打开时不擅自取得暂停权。提供带到期时间的“人工保留”开关；外部终端/网页活动不保证可被自动识别，不能承诺自动发现所有人工使用。

启停操作绑定控制器激活代次并串行协调。进入暂停后新任务仍持久入队：尚未发出暂停则取消 draining；已发出则等待该操作收敛，核查状态后再恢复。平台若不提供条件写入，不能假设本地代次可以阻止已发送的远端暂停请求；必须核对在途操作，不能边等旧暂停边启动新执行。

### 5.3 免费实例限制

根据本次已核对的官方公开文档，免费档默认连续运行上限为 480 分钟，平台可能提前暂停，保活或任务租约不延长最大运行时长；连续触顶后的冷却还会递增。

控制器读取实际限制和 `cooldownUntil`，尊重 `Retry-After`、429 和账户级速率限制，不硬编码“20 分钟后一定可用”。暂停可以恢复内存，也可能退回冷启动；磁盘保留不能代替异地备份。

长任务必须切成可确认的小单元，不以“还有八小时”作为安全假设。运行预算不足时不领取长单元，但仍按任意时刻可能中断设计。平台强制暂停或冷却不会影响 VPS 阅读服务，只影响任务完成时间。

## 6. 第一阶段：小规模、无第三方凭据的执行闭环

### 6.1 独立交付目标

完成一次“VPS 持久提交 -> 启动 InstaBox -> worker 领取 -> 生成文件 -> VPS 校验并保存 -> 用户取得结果 -> 空闲暂停”的可恢复闭环。

第一阶段仅允许诊断任务和单本 EPUB 导出试点。不迁移收藏同步、签到或定时备份，不建设通用远程命令平台。

### 6.2 为什么用 EPUB 试点

`epub_exporter.py:create_epub_from_novel()` 已将小说元数据、正文和可选封面转成 EPUB 字节，不打开业务数据库，也不登录 Pixiv。它能验证真正的输入和文件回传，而不是只证明一条 ping 成功。

VPS 生成不可变输入快照，包含必要元数据、正文、可选封面字节、渲染器版本和输入摘要；worker 使用任务工作目录渲染，并回传文件。先用合成小说完成验收，再由用户显式选择一本真实小说进行试用。

一期只处理单本，输入正文上限 16 MiB、封面上限 5 MiB、输出上限 32 MiB；超限在派发前拒绝或在接收时失败，不悄悄截断。每次执行的任务时限为 10 分钟，冷启动等待不计入渲染执行时间。远程手动导出默认一小时内完成，超过截止时间显示过期，不继续唤醒。

当前同步导出接口保持原状，不能把原本返回 EPUB/ZIP 的请求改成任务 JSON，或让普通下载请求等待云端冷启动。远程试点使用独立的显式提交、状态查询和下载入口，不占用现有 Pixiv 同步执行槽。

本试点验证的是架构可靠性，不承诺单本导出值得支付冷启动和传输成本。现有本地导出继续可用，不设置失联后的隐式跨端双跑。

### 6.3 一期模块边界

| 模块 | 责任 | 与现有代码的关系 |
|---|---|---|
| 远程任务协调器 | 持久事件、领取、租约、失效隔离、重试和结果收口 | 拟新增；不将 `JobManager` 内存对象直接搬过网络 |
| InstaBox 适配器 | 生命周期请求、operation 跟踪、冷却/限流和就绪 | 拟新增；仅 VPS 持有管理 key |
| worker 协议及入口 | 注册、取任务、心跳、限时执行、结果上传 | 拟新增专用入口；不调用 `create_app()` |
| 结果接收/存储 | 暂存、大小与格式校验、持久化、授权下载 | VPS 本地；不接受云端任意路径 |
| EPUB 适配器 | VPS 冻结输入，worker 复用渲染函数 | 复用 `epub_exporter.py`，保持当前正文插图处理语义 |
| 状态展示 | 队列、冷却、运行、待核实、失败、成功与最后确认时间 | 远程记录为事实来源；既有任务状态不被误改 |

API 的具体路径、字段类型、迁移脚本和逐步测试在这份详细设计获认可后写入一期实施计划。它们不能先于权限和失败语义随意扩展为通用 RPC。

## 7. 后续独立阶段

### 7.1 签到适配

先取得并审阅签到项目代码及现有运行方式，确定站点业务日、触发时段、最晚补签时间、是否可查询已签到、登录刷新、持久文件及重复提交语义。

没有这些证据前，将签到视为不可盲目重试的外部副作用。不会把任意命令文本塞入通用任务消息；适配器调用固定的受支持入口。账号资料与操作记录的权威存储和恢复规则单独设计。

### 7.2 Pixiv 抓取迁移

先试点 VPS 指定单本小说的抓取子任务，再扩展批量同步；不直接在云端执行现有 `sync bookmark` 并回传数据库。

`jobs/quick_sync.py` 和 `sync_engine.py:_sync_novel_inner()` 目前混合认证、网络抓取、本地归档和数据库更新，需要明确拆分：云端抓取/规范化，VPS 决定是否采用、生成路径、写归档、更新索引和水位。

VPS 继续主导收藏列表顺序、来源归属、分页完整性及总体完成判定。保留现有 `incomplete/truncated/fetch_failed` 分类；部分结果不能被当成完整列表用于删除判断，也不能简单按最大 novel ID 推断新增收藏。

迁移某项任务时，原本 local 和新的 remote 路由共用账户/业务范围互斥及限流预算。先验证云端 Pixiv 连通性、出口变更引起的认证/风控及最小凭据范围，再考虑扩大迁移。

### 7.3 阅读进度统一

保留同一访问域名，新增节流服务端自动保存、服务端版本比较以及离线待同步记录。旧浏览器缓存不能无条件覆盖更新的服务端进度；冲突不能简单取最大百分比，因为重读/回退也可能是用户意图。

这是一项独立的用户体验和数据一致性工作，不依赖 worker 是否在线，不在一期生命周期试点中顺手改动。

## 8. 验收、恢复和回退

### 8.1 一期验收

1. 实例暂停时，VPS 阅读、搜索、登录和原有本地导出保持可用。
2. 同一请求重复提交、两个 worker 同时领取，仅产生一个业务事件和一个有效执行租约。
3. 生命周期返回 202、实例显示 running 但 worker 未就绪时，不错误派发或显示任务成功。
4. 模拟冷却、429、启动超时和提前暂停：遵守退避、不忙循环、不丢任务；截止时间后停止重试。
5. 同一文件重传得到原确认；旧 attempt 迟到、摘要不符和越权上传被拒绝。
6. 在文件写入前、写入后/数据库提交前、提交后/响应前分别模拟中断：恢复后无损坏引用、无重复发布。
7. worker 断网、VPS 重启和云端冷启动后按持久记录恢复；旧会话不直接续跑，任务日志不被一律错误标失败。
8. draining 期间到达新任务或人工保留需求：任务不丢失，在途启停有明确收敛路径，不向正暂停的实例派发。
9. 实例由用户手动打开时不自动暂停；控制器不操作配置目标以外的实例。
10. 任务协议版本不匹配、输入超限、路径穿越和任意命令请求均被拒绝；日志不含业务秘密。
11. 合成小说的远程 EPUB 与本地导出内容语义一致，原同步下载接口的响应契约不变。

先使用 fake provider、fake worker 和临时数据库做自动测试；真实账户验证必须另行确认目标实例、权限及运行窗口，不把测试工具启动当成生产部署。

### 8.2 备份与回退

VPS 使用 SQLite 一致快照或受控停写备份，同时覆盖归档、配置及解密所需密钥，进行加密和异地保留；云端缓存不作为备份来源。

恢复旧备份后，在重开任务 API 前更新执行世代并撤销旧会话/执行凭据，防止还活着的旧 worker 使用回退后的租约或代号提交。对未知外部副作用保留人工核对流程。

回退时先停止新远程派发、撤销当前 attempt 并处理未确认结果，再关闭远程功能开关。VPS 原有阅读和本地导出不变；一期未迁移生产同步任务，因此回退不需要合并云端数据库。

签到或同步迁移以后，其回退也必须先处理进行中的远端副作用与写入权限，不能简单打开本机 cron 造成双跑。

## 9. 部署前事实核对与设计审阅

这些是部署门槛，不应被本设计写成已经满足：

- 生产 VPS 的实际版本、资源余量、数据库/归档位置及可恢复备份。
- 目标 InstaBox 的实例身份、实际限制、剩余存储、出站配额，以及该实例是否也用于手工工作。
- VPS 与云端 HTTPS 的双向业务连通性；worker 是主动连接，不以能 ping 通代替协议测试。
- systemd/等效服务是否在冷启动后启动 worker、实际就绪耗时及暂停/恢复行为。
- 签到项目的目录或仓库、运行入口和副作用语义；在接入阶段之前不索取或复制账号秘密。

用户已认可的重点：保留 VPS 主库和阅读服务；取消固定晚间保活；一期用无账号凭据的单本导出试点；失联不盲目重试外部操作；不擅自暂停手动打开的实例。
