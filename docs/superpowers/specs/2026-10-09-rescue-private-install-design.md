# 救援用户脚本：自用安装设计

## 已选方案

维护者选择“只供自己安装”，沿用现有 GitHub 仓库提供直装入口，不发布到 Greasy Fork 或其他脚本平台。手机浏览器已有脚本安装功能，但具体浏览器和 GM API 支持范围未知，因此同时提供直装和导入说明，不承诺已在手机上安装成功。

## 范围

- 发布源固定为 main 的 `userscripts/pixiv-rescue.user.js`；安装、更新均使用同一条 HTTPS 原始文件链接。
- 版本从 `0.1.0` 升到 `0.1.1`，添加 `@downloadURL`、`@updateURL`、作者、MIT 许可、项目和反馈链接。
- 保留 `@name`、`@namespace`、匹配页面、四项 GM 权限、单一 `@connect` 域名和现有 Token 存储键；不扩权，不改救援运行时代码。
- 默认服务器继续是 `https://pixiv.dongboapp.com`，自用安装不需要更换地址。
- GitHub 文件仍是公开源码，但不包含个人 Token、密码、书库或小说正文；不改变仓库可见性和任何权限。
- README 提供直装入口，救援指南解释手机安装、导入备用方式、Token 配置和后续更新。
- 不创建/登录脚本平台账号、不操作服务器、不生成或轮换凭据，不改变 ai-writing。

## 安装与更新

标准支持用户脚本的管理器通过 `.user.js` 链接显示安装确认。若浏览器只展示源码，则使用其“从链接安装/导入”；没有该功能时，可将完整源码导入或粘贴到新脚本。入口名称因浏览器而异。

安装后，在 Pixiv 小说或系列页面打开脚本菜单，填写已有救援 Token。只有从未配置或 Token 遗失时才由维护者在系统维护页生成；轮换会立即让所有设备上的旧 Token 失效。不能把 Dashboard 访问密码当作救援 Token。

支持 `@updateURL` 的管理器按自己的设置检查更新；不支持自动更新的内置管理器需要重新打开同一安装链接更新。不在脚本内增加更新轮询。覆盖升级不要先卸载，保持脚本身份和现有存储键；Token 的最终保留行为由管理器决定。

## 验收

- 新元信息/文档契约先 RED 后 GREEN；既有静态脚本和 README 契约保持通过。
- Node 语法检查通过；JavaScript 正文与改动前逐字一致，后台调用范围不变。
- 文档安装 URL 与更新 URL 一致且不携带令牌；官网、源码和问题入口清晰。
- 发布到既有 main 后验证 GitHub 原始文件返回正确脚本及版本；不将源码链接可下载等同于手机已安装或真实救援成功。
