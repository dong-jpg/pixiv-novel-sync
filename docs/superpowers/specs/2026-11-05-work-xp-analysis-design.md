## 1. 目标与范围

首版回答“这部作品写了什么、有哪些题材/关系/情境/叙事特征、判断依据在哪里”，不直接回答“用户喜欢什么”。一次分析只接受用户明确选择的一篇已归档小说或一个已归档系列。

交付闭环：选择作品及分析 Agent → 核对正文范围、章序、外发目标和预算 → 显式开始 → 全文覆盖处理 → 带版本与原文证据的作品报告。

必须提供：

- 正文范围与章序确认；缺章、空正文、连载和未知状态的独立提示。
- 整部输入可容纳时整体分析，超限时按章/块提取，再跨章汇总；不能用开头抽样代替全文。
- 题材、关系、情境、语气、节奏、叙事等作品特征，以及有证据支持的 XP 相关内容标签。
- 原文版本、覆盖统计、可追溯引文、明确的不确定性与反例；“推测”不能显示成事实。
- 整部预算、已验证单元检查点、取消/恢复、同步任务优先和敏感业务产物的删除。

本首版不做：

- 自动扫描全库、自动处理新同步作品、跨作品批量分析或定时付费分析。
- 根据普通归档、收藏、追更或“感兴趣”推断已读/喜欢；不生成个人性格、性取向或其他身份结论。
- 自动写回个人偏好画像、推荐评分/搜索、收藏/关注或调用 Pixiv 补章。
- 写作/成人润色模块回迁、向量库、RAG、工具执行循环、多 Agent 投票、第三方 Agent 框架。
- 实际金额硬预算或厂商 token 精确计费保证；估算与已报告用量必须分开。
- 修改第一阶段一般调用的 `metadata_only` 留存方式，或开放其目前不支持的 main continue。

## 2. 路线比较与选择

| 路线 | 好处 | 局限 |
| --- | --- | --- |
| 整部一次调用 | 全局上下文直接可见；短作品调用少 | 装不下就无法处理；失败重试需要重发整部 |
| 所有作品固定逐章分析 | 覆盖和检查点统一，局部重试容易 | 短作品也产生额外调用；跨章关系依赖汇总 |
| 整部优先、超限分章/块（本稿采用） | 使用第一阶段逐候选容量规划，兼顾大上下文与长篇 | 两条路径都需要测试；汇总不能伪装成再次读过全部原文 |

`auto` 是首版唯一执行策略，不增加一组未经实现的调度模式。预览时对“完整消息 + 输出预留”调用现有纯预检：有合格候选则计划整部；没有合格候选，但存在协议/能力/绑定可用且仅因输入容量被排除的候选，才计划分章/块。其他禁用/不兼容候选继续排除，不妨碍这一容量降级。缺 Key、禁用 Agent、无绑定或全部不支持所需能力时直接显示配置问题，不借分块隐藏它。纯预检不验证真实认证/连通性，不能把本地配置可用写成远端服务已通过测试。

实际调用失败后不偷偷切换处理粒度，不临时放宽预算或选一个未确认的 Provider。需要改计划时重新预览、确认；正常候选故障转移继续遵守第一阶段冻结链和正文发布边界。

## 3. 当前可复用能力与缺口

| 已有能力 | 不能据此声称已有的能力 |
| --- | --- |
| `novel_texts.text_raw/text_hash/fetched_at` 与完整正文读取 | 历史正文版本或不可变全文快照；当前行会被同步覆盖 |
| 系列、来源、远端数量与本地正文数量 | 可靠作者章序或已完结证明；部分详情会用本地数覆盖远端数 |
| `AIWritingService.invoke_text` 和纯 `preflight_agent` | 正文读取、业务 JSON/证据验证、作品级预算、业务恢复 |
| Router 的发送前事务、单 AI job 的 16 候选/32 请求/30 分钟上限 | 多个子调用合起来的总上限 |
| 单槽 `JobManager`、共享 `JobRunner`、优先级与协作取消 | 持久化作品检查点；内存 JobState 不可充当断点库 |

现有整系列正文 getter 只按发表时间排序，返回值缺少章 ID/hash；不能直接拿它的字典作为新的 Provider 输入。新增窄投影只读取本功能需要的字段，不携带 `raw_json`、账号、归档路径、Key 或代理配置。

## 4. 本地清单、章序与版本

### 4.1 清单形成

预览以 `source_kind=novel|series` 和数据库 ID 定位作品，不接受任意文件路径、SQL 或客户端自带正文。系列默认列出该系列当前归档的所有章节，包含短章与空正文状态；不得沿用偏好统计“正文至少 1000 字”的过滤条件。

在同一个短读事务中取得：

- 作品/章节 ID、标题、顺序与顺序来源。
- 正文的 SHA-256、Unicode code point 长度、UTF-8 字节数、获取时间。
- 已知远端期望章数及其观察时间、本地章节数、有正文数、缺失/空白项。
- `publication_state=unknown|ongoing|completed` 及声明来源；默认 unknown。

hash 对准确的当前 `text_raw` 计算，编码为 UTF-8；存量 hash 不一致时拒绝创建分析并提示数据需要核查。本功能不再次 NFC/空白归一化、去除 Pixiv 标记或默默裁剪正文。数据库事务不跨网络调用，不在只读事务内嵌写事务。

### 4.2 章序与完整性

现有发表日期只能生成“建议顺序”，使用 ID 作稳定同值排序，不标为已核实章序。没有可靠顺序来源时，用户必须在预览中确认/调整本次章序；确认只属于本分析，不顺便改全站系列排序。

章节顺序提交必须是本次所选系列清单的排列，不能混入其他作品，也不能通过重排悄悄丢章。若本地数量少于有效远端期望值、有空正文、出版状态 ongoing/unknown，或缺乏可靠远端完整清单，开始前必须单独确认“仅分析当前可用归档版本”；缺失/空白/未知项仍保留在清单与报告中。没有远端完整清单时，不能捏造缺失章 ID/位置。目标没有任何非空正文时禁止开始，不能用空分母得到 100% 覆盖。

远端数与本地数相等也不证明作品已完结。用户标注完结/连载时记录 `user_declared`，不能改写成服务端验证事实。

### 4.3 冻结的是清单，不是新增全文副本

创建任务时再次核对预览 fingerprint 与当前数据，在一个写事务中持久化不含全文的不可变清单和预算。预览后新增/修改/删除章节、重排、改 Agent 或改预算导致 fingerprint 不匹配时返回冲突，不能分析另一个版本。

首版不新增可用于完整重放的原文副本/输入快照。执行每个原文单元前重新读取所需正文，严格核对清单 hash，再以该内存副本构造完整输入。正文保存/删除路径仅在**实际源 hash 改变或正文被删除**时，在其事务内标记关联未完成分析失效并撤销发送权；完成报告标旧版或按删除规则清理。同 hash 的重复保存、元数据/fetched_at 刷新不能误使任务失效或将成功报告标成正文旧版。单元/最终报告提交事务同时验证失效标记、所引用源 hash、清单与 owner，不允许最后一次原文读取后的正文改变在汇总阶段漏检。新业务源关联必须可索引，不为这项检查扫描所有历史报告。

正文变化或删除后，未完成任务停止为 `invalidated`，保留安全原因，不混合新旧内容继续；用户需要为新版本重新预览并建任务。首版只在同一父任务内复用匹配版本的已验证检查点，不做跨任务/跨作品的自动缓存共享。

创建后的系列新增章节不自动加入已确认清单；若原清单条目的正文均未改变，可完成原清单，但报告明确标为“截至创建时间的归档版本，非最新”，不能把新章算入覆盖。已选章节正文变化/删除的处理仍按前述失效规则执行。

## 5. 分块、全文覆盖与汇总

### 5.1 原文单元

- 整部路径：完整可用正文按确认章序进入同一次调用，携带明确的章节/段块标识。章节块封装为有界消息，不按每段机械创建一条 message；每次调用最多 256 条消息、JSON 不超过 16 MiB。
- 分章路径：优先保持章节边界；超大单章按段落切块，极长单段再按 code point 安全边界拆分，绝不切断 Unicode 字符。
- 每块记录原文主区间 `[start, end)`；可携带相邻块最多 512 code point 的上下文，重叠部分不重复计算覆盖。
- 切块以真实生成消息的纯预检结果为准，包含系统指令、保存的 Agent 提示、标识、正文及输出预留。不能按“字数大概等于 token”直接宣称能放下。
- 每块继续逐候选预检，允许排除较小的后备模型；不能重新采用跨候选 max(input)/min(window) 的公共最小窗口。

切块算法/版本、原文主区间、重叠规则和原文单元清单在开始前冻结；必须验证主区间并集精确覆盖全部选定的非空正文，无缺口、无非法越界。

### 5.2 分层汇总

提取调用输出有界的结构化特征、已验证证据和不确定性。跨章调用只消费这些已验证产物及其 ID，不凭摘要声称又读了一遍全部原文。整部路径中，一次返回的验证报告本身就是图的最终根节点，不强制再增加一次汇总调用。

预览不能精确知道未来生成结果大小，因此显示“已确定的原文单元数、汇总最少次数、保守预算说明”，不伪造完整精确调用数。汇总阶段以实际产物按固定算法分组，逐组纯预检；每层最多合并 16 个子产物，最多 8 层。派生图和输入产物 hash 必须在发送前落库，恢复时复用同一图。

较大产物可以按完整 claim 记录分组，不可截断一个 claim 或丢弃其证据引用以强行装入窗口。单条记录仍装不下，或无法在层数/单元数/预算内形成最终报告时暂停并解释原因，不能假装汇总成功。

### 5.3 覆盖指标的含义

报告分别记录：

- `validated_input_coverage`：结构与证据验证成功的原文单元主区间并集，占本次可用正文的比例；重叠只计一次。
- `source_completeness`：所选本地清单与已知出版作品之间的缺章/未知/用户声明状态。
- `synthesis_complete`：派生汇总图是否成功到达最终报告。

“输入覆盖 100%”不表示模型理解绝对正确，也不证明未知连载已经完结。只有全部计划原文单元有效、最终汇总通过并完成原子发布，父任务才成功。缺章确认后的成功标题仍为“当前归档版本分析”，不能写“整部原作完整分析”。

## 6. 作品报告与可核验证据

报告 schema v1 包括：作品/清单版本、范围与覆盖、内容概述、主题/关系/情境/叙事特征、XP 相关内容标签、证据引用、反例/矛盾、不确定性、各单元实际模型及已报告用量。

每个实质性内容结论必须引用至少一条可验证证据；跨章关联结论必须指明支撑章节，不凭单句泛化为全书。结论区分“直接文本依据”“解释性判断”“证据不足”；置信程度不是厂商统计概率。

### 6.1 定位由服务端确定

Provider 输入中给每段块分配稳定 `block_id`；Provider 返回 `block_id` 与原文原样引文，不要求模型自行数整章的字符偏移。服务端仅在对应单元的已发送块内匹配引文：

- 引文必须是准确子串且在该块内唯一；匹配不到、歧义、超出已发送范围或 hash 不符均拒绝，不猜第一处、不模糊修正。
- 服务端生成章节 ID、源 hash 和零起点、左闭右开的 code point 偏移。浏览器不能用 JavaScript UTF-16 下标重新定义位置。
- 单条引文最多 240 code point，每个结论最多 4 条；报告最多 128 个结论。
- 汇总输出只能引用输入允许的证据 ID，不能另造引文、扩展范围或引用失败单元。

持久化结构中禁止任意附加字符串字段：标签/短标题不超过 80 code point，单条结论/理由不超过 600，单元概述不超过 2000，最终概述不超过 4000；单元最多 32 个结论，不确定性/反例各最多 32 条且每条最多 600。全记录还受 JSON 字节上限约束。超界拒绝而非静默截断，摘要字段不能替代原文重放存储。对于极短章节，合法的短引文可能恰好覆盖整章；“不保存完整输入快照”不等于保证引用与原文永不完全重合，此边界必须在产物留存说明中明确。

自动检查证明出处和结构，不证明解释必然正确。用户可以通过登录后的证据入口展开短引文、跳转同 hash 的正文，核对或标记结论不可靠。

源正文后来更新时，既有成功报告标为旧版本；引文可作为当时验证过的短证据显示，但当前正文跳转必须拒绝 hash 不符并说明原因，不将旧偏移应用到新正文。

### 6.2 输出失败

解析、schema、引用或范围验证失败的单元不能变成检查点。首版不做无限自动 JSON 修复，也不把 partial 文本交给下一层。现有传输重试/fallback 仍受预算约束；业务输出验证失败后保留安全错误码，用户显式恢复才允许重试该单元。

空特征列表可以是有效结果，但必须返回“未找到足够依据”的结构化说明；不能把空响应当成“作品没有这些特征”。最终报告不展示提供商错误原文或失败输出。

## 7. 任务与最小持久化边界

只增加一个新的业务类型 `work_analysis`，使用既有共享 JobRunner/JobManager 获取执行槽；不创建第二套线程池、消息队列或前端轮询驱动的执行系统。内存 JobState 的 params 只含父任务 ID，不放正文或报告。首版仅通过现有单一 Web 调度 owner 执行，不增加绕过共享槽的 CLI/多 worker 执行入口。

必须增加窄的共享准入桥接，不能把它当作现成能力：当前 `_submit_shared_job` 在占用时拒绝，JobRunner 获取槽失败会直接失败，而既有抢占 watcher 只包围调度器发起的任务。桥接在手动创建/恢复、共享 worker 的完成回调和既有调度 tick 被唤醒，先安排更高优先级同步，再尝试一个待运行分析。待运行父意图保存在本业务表，不预先启动一个会争槽失败的 worker。

手动高优先级同步遇到分析占槽时，可进入**同一 JobManager** 的有界待运行项并请求当前分析让位，由同一完成回调接续；不新建旁路队列。对非作品分析的现有忙碌处理不作无关重写。为手动发起的 work_analysis 注册/复用既有抢占 watcher，而非只给任务加一个 priority 字段。

关闭自动同步后，不产生定时同步候选，但用户提交与共享完成回调仍负责准入及 sync_yield 的恢复，不依赖 AutoSyncScheduler 正在运行，也不依赖页面打开。进程启动只做失效/恢复状态整理，不自动激活上次中断的付费任务。

建议使用 4 张业务表，详细 DDL 在实施计划中逐项落实：

| 表 | 主要职责 |
| --- | --- |
| `work_analysis_runs` | 不含正文的冻结清单、Agent/算法/schema 版本、确认记录、父状态、epoch/lease、累计预算与变更记录、完成报告、删除墓碑 |
| `work_analysis_sources` | 每父任务的有序源 ID/hash/长度/缺失状态；提供按 novel ID 查询受影响任务的索引，不保存正文 |
| `work_analysis_units` | 原文区间或汇总子引用、输入 fingerprint、状态/尝试号、关联 AI job、验证通过的结构结果和短证据 |
| `work_analysis_requests` | `(child_job_id, request_ordinal)` 唯一关联、父/单元/epoch、预算预留和归一化用量状态 |

报告与单元结果是明确授权保存的本地敏感**业务产物**，不是通用 AI 日志的旁路；schema/权限/删除/大小限制必须独立实现。这 4 张表不保存完整输入/重放快照（有界引文的短章例外见 §6.1）；业务产物也不得顺手复制到 `ai_jobs`、attempt、task_logs、进度或错误字段。

运行 identity 至少含清单、chunker、提取/汇总 prompt、报告 schema、Agent 和冻结配置版本。一般调用当前没有父预算绑定/子 job 创建回调，实施需要窄的服务端内部扩展，不能在文档中当作现成功能。

### 7.1 父任务所有权

每次获取共享槽后，在事务中领取递增 epoch 和有限租约；旧 worker 不能获得新的发送预留、退还预算、写检查点或发布报告。租约仅属于新业务父记录，不给所有旧 `task_logs` 加 owner lease，避免恢复旧 OUT 范围。

创建 AI 子 job 时就在同一持久化路径关联父 ID/epoch/单元/尝试，不能等回调完成才登记，否则崩溃后无法判断已经花费的调用。

单元结果、证据验证、覆盖更新及单元完成标记在同一事务提交。最终报告和父成功状态也原子提交，失败不会覆盖原有有效结果。唯一键阻止双击开始、重复排队和旧 owner 迟到写入造成双重工作。

最终发布必须使用 JobRunner 已交给 executor 的 `claim_finalization()`：在敏感业务提交**之前**领取，不能等 executor 返回后才领。作品暂停/取消、通用共享任务取消和调度让位统一走工作专用控制适配器：有活动共享 job 时，先取得其取消许可，再持久化父停止意图；若 finalization 已先领取则返回“正在完成”冲突，不谎报取消已接受。停止持久化失败不返回成功；共享取消信号仍阻止 worker 发布。无活动 worker 的 queued/paused 状态通过父 CAS 直接控制。

领取 finalization 后，数据库发布事务仍必须检查父停止/失效/删除标记及源版本；源变更/删除可以在 DB 层先胜出使发布失败，不能被内存 claim 绕开。事务失败由现有 claim abort 路径释放；提交后到共享状态完成期间不再接受普通取消。崩溃后以父事务结果为事实源修正本业务的任务状态投影，不重新生成已经提交的报告。锁顺序和取消/发布两种胜出顺序必须写成执行计划中的并发回归。

## 8. 整部预算：硬限制与估算分开

### 8.1 必须显式确认的预算

创建任务必须提供有限的请求次数、计划 token 和累计活跃执行秒数。界面可以给出建议值，但缺失、0、负数、无限、NaN 或未确认都不能开始。预览和确认本身不调用 Provider、不花模型费用。

首版资源保护提案：

| 约束 | 上限/规则 |
| --- | --- |
| 同一父任务实际发送预留 | 512 次；用户填写 1–512 的更紧上限 |
| 累计活跃执行时间 | 14400 秒；用户填写 30–14400 秒 |
| 计划 token 额度 | 100000000；用户显式填写更紧的正整数额度 |
| 当前归档原文 | 总 UTF-8 不超过 64 MiB、最多 2048 章 |
| 原文和汇总单元总数 | 512；超过时阻止/暂停，不截掉尾部 |
| 单次原始/汇总输入 | 继续满足第一阶段有界消息与容量检查；序列化 JSON 不超过 16 MiB |
| 单元业务结果/最终报告 | 分别不超过 128 KiB / 1 MiB（UTF-8 JSON 字节） |

这些是拟定的软件保护上限，不是用户支出授权或推荐花满额度。UI 不得把上限填成无提示的默认预算；不足时让用户缩小范围、调整明确 Agent 或修改预算并重新确认。

### 8.2 每次真实发送前原子扣账

将服务端类型化的父/epoch/单元绑定沿调用链传到现有 `claim_ai_job_network_request`，在它**同一个发送预留事务**中完成：

1. 校验父/子所有权、取消/让位、租约、deadline、清单及配置身份。
2. 校验父剩余请求额度及该候选的计划 token 额度。
3. 同时分配子网络 ordinal、增加父累计发送预留、写入父子关联和用量未知记录。
4. 事务成功返回后才允许 Session 发送；任一步失败都不发送。

不能在现有方法外套一层它不支持的写事务，也不能靠轮询 stop callback 冒充原子预算准入。重试、空流 fallback、候选切换、重新执行失败单元都走同一路径。第一阶段每子 job 的 16 候选/32 请求/30 分钟硬限制仍保留。

事务提交是“本地授权一次发送”的线性化点。已经预留的调用算在途/结果未知；取消可能发生在预留提交与物理 socket 发送之间，发送前仍做最终尽力取消检查，但不能承诺撤销后绝无物理发送。此竞态不退款，取消不能获得新预留，也不能将之后返回的内容发布为有效单元。

提交预留后、是否已发送不确定的请求保守计费，不在重启时退款。计划 token 按**实际候选**的现有保守输入估算（包含其安全余量）加请求输出预留扣账；它约束本地规划估算，不保证厂商真实 token 或金额绝不超出。已报告实际用量另存且按 ordinal 幂等汇总；未知不补 0，也不据此释放估算额度。

### 8.3 活跃时间与恢复

活跃时间包含领取执行槽后的准备、生成等待、重试退避和提交；不包含排队、正常暂停或离线等待。每次激活先持久预留一个不超过 30 分钟且不超过剩余额度的时间片；各子 deadline 同时受时间片与原子 job 限制。

正常结束用 monotonic 耗时结算并归还未用时间，只有当前 epoch 能归还。正常 pause/cancel/yield 先持久化停止意图来禁止新预留/发布，**不立即递增 epoch**；原 worker 只保留心跳、用量归并和一次时间结算权限，真实退出时在同一事务结算、转为暂停/取消并撤销 epoch。进程丢失、删除或源失效需要立即撤权时，由协调器保守扣完整个未结算时间片，旧 owner 不能迟到退款。

这样正常五秒让位不会被误算成三十分钟，而崩溃也不能利用重启清零预算。这是本地激活/发送准入及 deadline 预算，不保证超时瞬间远端停止计算，终止等待不得被 UI 隐藏。

预算耗尽进入 paused，不启动下一个调用。用户可通过带版本 CAS 的预算调整明确增加尚未使用的上限；保留旧值、新值、累计预留与确认记录，不清零计数。增加不能超过服务器硬上限；配置/正文失效不能靠加预算恢复。

## 9. 暂停、取消、让位与重启

父状态：`queued / running / pausing / paused / cancelling / cancelled / failed / invalidated / succeeded`。pause reason 区分 user_pause、sync_yield、budget_exhausted、process_interrupted；failure reason 使用安全枚举。

- 用户暂停：阻止新发送，协作结束当前调用，保留已验证检查点；显式恢复后用同一预算继续。
- 用户取消：撤销当前运行意图，不再自动重排；保留检查点。用户以后显式“恢复未完成分析”才可重新排队，仍使用原清单/预算累计，不复活旧 AI job。
- 同步让位：作品分析低于收藏/追更同步。监听既有抢占信号，阻止后续发送，在当前请求真实退出、检查点安全处理后释放槽。`sync_yield` 可在同步空闲时继续用户已确认的同一任务；手动暂停/取消不能自动继续。
- 既有防饥饿策略不能把整部长篇提升为不可抢占任务；恢复只领取有界时间片，下一次更高优先级同步仍可请求让位。
- 进程重启：协调器在现有生命周期内扫描本功能未结束记录，撤销失效 owner、保守结算未知预留并标为 paused/process_interrupted；不自动重发可能已经付费的调用，等待用户恢复。
- 配置或原文版本不同：invalidated，需要新的预览/父任务。老成功报告只标旧版；不改写成新内容的报告。

不承诺立即终止 Provider 的远端计算。不能通过提前释放共享槽、留下旧 worker 在后台运行来伪造取消成功。未完成/未验证输出不发布给业务，也不算覆盖。

恢复走新的**业务恢复**入口，不调用 `/ai/jobs/<id>/continue`。后者仍按第一阶段返回不支持，不因新父任务而开放历史任务重放。

## 10. 隐私、外发与删除

- 开始确认页明确显示选定作品、可用正文范围、Agent、可能使用的 Provider/模型、预算与“正文将发送到这些服务”的说明。用户点击确认只授权这个任务，不是全库外发许可。
- Provider 无权访问数据库或文件；小说、标题、注释和模型输出均视为不可信数据。小说中的指令不能改变处理目标、要求调用工具、读取其他作品或泄露凭据。
- 保持统一调用 `metadata_only`；不能借用关键词清洗的 `keyword_compat` 来保存小说正文/报告。
- 业务表/报告 API 仅限现有 Dashboard 认证与 CSRF 边界；不暴露在 rescue API，不加入公开目录/FTS，不把正文或报告放进 URL/localStorage。
- 所有报告/证据响应 `Cache-Control: no-store`。HTML 使用文本节点，证据默认折叠；摘要不得默认展开大段敏感原文。
- 删除分析先撤销 epoch/后续发送并设置删除墓碑，再清除报告、单元结果、证据及可恢复输入引用；正在返回的旧请求不能重新写回。只保留必要的无正文计数/审计，不保留标题、引文或结论；删除墓碑独立于运行状态且禁止任何 resume。
- 删除参与分析的归档正文/作品时，同步失效关联运行并清除其敏感分析产物，不能靠检查点恢复已删除内容。普通正文更新只标记版本变化，不自动把新内容发送出去。
- 应用层删除不保证备份/WAL/存储介质中立即安全擦除；备份保留由既有策略管理，UI 文案必须说明这一边界。

## 11. UI 与业务 API 草案

不新增全站导航或前端框架。单篇/系列详情提供“分析作品”；进入现有偏好页面下独立的“作品分析”视图，不能替换现有本地统计/默认画像。

创建流程：选择已配置 Agent → 清单/章序确认 → 零网络预览 → 查看容量、外发与预算 → 显式开始。预览期间修改目标、顺序、Agent、预算会使旧预览失效；按钮和方法入口都必须拒绝过期确认。

| 接口（统一前缀 `/api/dashboard/work-analyses`） | 行为 |
| --- | --- |
| `POST /preview` | 本地读取/纯预检，返回安全清单、风险、计划和 fingerprint；不建执行 job，不 probe Provider |
| `POST /` | 用当前 fingerprint、确认项、Agent、预算和幂等键创建父任务；不同 payload 复用幂等键返回冲突 |
| `GET /`、`GET /<id>` | 分页列表/安全状态，范围、计数、预算、错误码；不顺带返回正文/完整报告 |
| `POST /<id>/pause`、`cancel`、`resume` | 带 expected_version 的业务状态迁移；恢复不清零预算，不复用旧 continue |
| `POST /<id>/budget` | 显式、带 CAS 的预算调整，不能暗改输入/Provider 或超出硬上限 |
| `GET /<id>/units` | 分页单元元数据、覆盖和诊断；不默认展示中间敏感文本 |
| `GET /<id>/report` | 仅成功且未删除的验证报告；未完成返回 409，不冒充完整报告 |
| `GET /<id>/evidence/<evidence_id>` | 认证后取有界证据；无权限/不属于报告拒绝，正文版本失效明确提示 |
| `DELETE /<id>` | 幂等删除，先撤销运行权再清除敏感产物 |

参数错误为 400，身份/CSRF 复用现有 401/403，不存在为 404，过期计划/状态/CAS 为 409，输入或产物超界为 413。删除或当前正文不再支持跳转的证据请求可返回 410，并给安全原因。

首版使用现有轮询，不为偏好页面增加 SSE。共享模型选择器仍负责精确不透明 key、当前绑定保留及失效项解释；不增加自动测试生成按钮。

## 12. 一致性、故障与事务验收

| 故障边界 | 必须出现的结果 |
| --- | --- |
| 预览后正文/章序/配置变化 | 创建冲突，零 Provider 请求 |
| 创建幂等请求重复/双击 | 同一父任务，不生成两个付费任务 |
| 子 job 创建后、发送预留前崩溃 | 有父子关联，可确认未预留；不宣称已经发送 |
| 预留后、响应前崩溃 | 请求/估算额度不退；用量未知；没有有效检查点 |
| 响应后、业务事务前崩溃 | 单元未完成，可显式重试；不得免费假定旧请求没发生 |
| 单元事务提交后、进程退出 | 恢复直接复用有效单元，输出与覆盖不会只提交一半 |
| 取消/让位/删除与响应并发 | 旧 epoch 不发布、不退款、不补写敏感产物 |
| 同一请求重复/乱序报告 usage | 按父子 ordinal 幂等投影，不重复计入；unknown 与 0 分开 |
| 源正文被覆盖或删除 | 不混合版本，不自动补章/重发，不应用旧偏移 |
| 预算剩余恰好在两个请求边界 | 只允许事务先获得额度的一次发送，绝不超发 |
| 正文中包含指令、HTML、相同引文或 emoji | 作为数据处理，拒绝歧义引用，正确 code point 定位，无 HTML 执行 |

所有默认自动测试使用临时数据库、合成正文和 fake HTTP/DNS，不接生产库、Pixiv 或付费 Provider。

## 14. 开发次序与审批边界

实施按同一首版目标分成：清单/纯规划与证据契约 → 业务存储和发送预算 → 共享任务/恢复/让位 → 模型输出/汇总验证 → 页面/API → 全面验收。不是先做一个会自动外发、再补隐私/预算的原型。

本文的详细设计和逐任务实施方式已获确认，现进入业务实现。编写计划和实施不代表获得付费调用、真实小说处理、推送或生产部署的自动授权。所有实际状态继续以 STATUS 为准，不将本稿标为功能 DONE。
