# 偏好学习与全库分析扩展

用户于 2026-11-12 明确要求一起实现上一轮剩余功能。本轮扩展此前仅手动单作品报告的范围，包含个人偏好 AI 总结、全库及新增/更新作品自动分析、反馈驱动的推荐闭环。旧文档中这三项的 OUT 标记不再作为禁止实现的约束；写作、自动收藏/关注及多用户系统仍不在本轮范围。

## 实现约束

- 作品报告继续走原来的 WorkAnalysisService、共享 Coordinator、Executor 和统一 Provider 路由，不新增付费执行队列。
- 全库以系列为单位去重，独立单篇单独处理；同正文版本的有效报告复用，已尝试的失败/取消任务不在下次扫描自动重发。
- 每个批次分配作品完整预算上限；持续策略的总预算和作品数量跨批次累计，不按 tick、重启或日期刷新。每次实际发送继续受原作品父任务账本控制。
- 新正文发现只登记元数据；配置变化需要重新确认，暂停/取消/关闭走既有停止握手。新功能默认关闭，用户从页面明确确认范围、服务商与预算后运行。
- 个人偏好依据用户明确的喜欢/不喜欢/中立评价。归档、收藏、已读、感兴趣均不自动记成喜欢。AI 输入使用当前有效的作品报告与显式评价，不再次发送全库正文。
- 个人画像单独版本化保存，通过服务端引用校验及源指纹检查后才能用于推荐；撤回评价、源删除或报告失效使相关画像失效。旧本地统计任务不覆盖该层。
- 画像的请求/token预留、子AI请求序号和用量在同一事务提交；沿用 metadata-only 通用历史、现有CSRF/认证、敏感结果默认折叠和 no-store。
- 推荐使用最新明确反馈及已启用的有效画像，保留硬屏蔽优先；每次推书重新构建搜索计划，标出推荐依据。

## 交付与验证

代码在 `codex/preference-intelligence` 隔离工作区实现。分别检查领域/存储、全库调度、前端状态机和应用集成，运行合成数据的端到端、预算竞争、失效/删除、旧功能回归、Node 与离线浏览器测试。部署脚本与迁移检查需要包含新表/静态资产；实际部署、真实服务调用、实际账单和真机体验独立记录，不以本地测试替代。

本地实现、独立复核和整体验收已完成。最终 Windows 2903 passed / 91 skipped、Linux 2852 passed / 142 skipped、Node 492 passed、显式离线 Chromium 75 passed，旧版本合成库两次迁移、静态和打包检查通过。实现与部署仍分开，详细结果见 [本轮验收记录](../../archive/PREFERENCE_LEARNING_ACCEPTANCE_2026-11-12.md) 和 [项目现状](../../STATUS.md)。本轮未部署或发起真实付费调用。
