## 性能与死代码

已落实的优化有可检查的数据库行为证据：

- 救援 lookup 从按 ID 重复取行 / 父系列 / 封面改为批量查询。1 项与 40 项均受固定查询上限约束，authorizer 断言不读取正文；救援目录列表仍用预计算投影和 SQL 分页，未改变收录语义。
- 远程列表原为一次列表连接加每条产物一次连接，50 条达到 51 次建连。现在同一 SELECT 联查唯一已发布产物；8 条真实 run 的测试断言只开 1 个连接。
- 偏好来源改为批量报告投影，单行限制大小且不读取小说正文；作品心跳采用轻量控制查询。推荐先执行屏蔽过滤，再决定是否请求系列统计，减少无用远端访问。
- 油猴已有缓存上限、每轮一次 lookup 缓存解析、15 秒首屏加速窗口、路由代次及有界批次；本轮补缓存身份与观察器释放。全页扫描仍有 3 秒兜底，不为降低计时器数字破坏 SPA 兼容。
- 清理 `sync/utils.py` 中已被 `pixiv_fetch` 替代的 `_extract_tags`、`_extract_cover_url`、`_extract_novel_text`、`_is_pixiv_image_url`、`_collect_asset_urls`、`_walk_urls` 及四个引入别名；跨两分支引用核查后删除。救援逐条封面存在性和 pending 查询也已由批量投影取代。

仍值得优化但没有贸然修改的部分：

| 优先级 | 机会 | 限制与建议 |
| --- | --- | --- |
| 高 | 长篇分块分析多次读取 / 编码 / hash 全部正文，近似 O(单元数 × 全文大小) | 按需要读取章节，汇总优先只读已验证产物；保留最终源版本 / owner / 证据校验 |
| 高 | 偏好心跳反复构建所有报告投影 | 用完整覆盖来源变化的 revision / 失效机制做轻量检查；先测真实反馈规模 |
| 中 | 远程 GC 无定时入口，过期文件仍占 1 GiB 配额 | 当前需显式 CLI GC；独立维护 timer 待补，未把保留阈值写成自动清理 |
| 中 | 空闲 worker 每次 claim 进行 fsync 探针，文件账本在事务中扫描 | 可先做轻量 gate / queued 检查，再保留事务内复核；需竞态回归 |
| 中 | 作品单元列表逐项读取用量、图片首屏加载 | 分组 SQL 和首屏可见性优化前先测量；不凭估计声称具体加速倍数 |

`checkin_status.py` 是未接线的后续适配器；`RemoteStore.close()` 是仍被调用的无资源兼容方法；旧本地统计接口与底层续跑校验仍有兼容用途。框架回调或仅测试引用不能直接视为死代码。

## 云主机执行完成度

`remote/contracts.py` 的任务集合、数据库 CHECK 和 worker 分派都只有 `diagnostic.v1` 与 `epub.single.v1`。它们有 11-12 真实闭环记录，但本轮没有启动云机或部署新版本。

- 已实现持久提交、冻结输入、幂等、session / epoch / fence、租约、断线恢复、上传 / 发布回执、按需唤醒和空闲暂停。
- Pixiv 单本 DTO / 抓取边界和签到只读网关已写好，尚无对应远程 task kind，也没有完成共享账户互斥、跨端限流、最小凭据、业务结果收口和副作用台账。
- 收藏、关注、追更、备份、状态检查、推荐、作品 / 偏好分析仍走本地通道；业务 cron 没有统一迁往云端。
- 跨设备阅读进度是独立已实现功能，不能与云 worker 迁移混为一项。
- VM 整机冷启动、强制中断、平台冷却、真实私人小说和独立异地备份仍需目标环境验收。

## 复杂度判断

明显维护负担是 `webapp.py`、`sync_engine.py`、`ai/model_router.py` 和写作专属大模块，以及多处任务注册表、重复校验 / 页面逻辑。适合按变更热点拆分和减少重复，不适合本轮做整架构重写。

预算账本、owner / lease、版本 CAS、结果发布回执、单槽与证据校验各自处理真实的付费、并发和恢复问题，不能仅凭层数认定过度设计。单用户 SQLite 书库也没有必要额外引入 Redis / Celery / Kubernetes。现有单进程 Web 约束应明确保留。
