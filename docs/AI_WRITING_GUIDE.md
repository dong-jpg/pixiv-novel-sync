# AI 写作使用与维护指南

本文仅适用于 ai-writing。该分支包含 main 全部书库、分析、偏好学习和本地执行基础，再增加创作项目、章节、向导、蒸馏、检索与局部润色。安装时选择 `--branch ai-writing`；更新脚本保留当前分支。

## 配置与入口

1. 配置稳定的 `PIXIV_NOVEL_SYNC_AI_SECRET_KEY`，在 `/dashboard/settings/models` 保存 Provider、同步目录并配置路由组。
2. 在 `/dashboard/settings/agents` 配置对应写作任务的 Agent。绑定模型的上下文、输出预留和服务商范围应与预期输入匹配。
3. `/dashboard/ai` 管理项目；`/dashboard/wizard` 用于对话构思；`/dashboard/novels/ai/<project_id>` 是创作小说阅读入口。章节、笔记与项目概览由项目内导航进入。
4. 成人局部润色还有独立确认、角色事实和三阶段 binding，按 [局部润色指南](ADULT_POLISH_USER_GUIDE.md) 配置。

同步和阅读不要求配置 AI。共享调用规则见 [模型路由指南](MODEL_ROUTING_GUIDE.md)；API 字段和准确路由见 [前端契约](frontend-api-contract.md)，不要照旧计划中的示例接口调用。

## 项目与章节流程

创建项目后保存题材、设定、角色、大纲和风格约束。可从归档资料提取风格/小说特征供创作参考；原始归档与项目章节是不同数据，不通过写作操作改写原小说。

在项目中建立章节大纲，再选择规划、续写或改写任务。输出先作为可检查的候选，核对后保存或应用。章节 Pipeline 按界面提供的阶段执行，阶段失败/取消不能当作整章已完成；应用前保留章节 revision 检查，避免覆盖另一标签页的新编辑。

章节摘要、关键事件、项目状态和伏笔可辅助后续上下文，但它们不是完整原文。需要长期一致性时先核对当前记忆内容；AI 生成和事实检查不能保证作品自动达到预期质量。

## 任务、继续与失败

AI 创作任务已迁移到全局任务日志。`/dashboard/logs` 可查看具体任务类型、状态、候选尝试、用量与脱敏失败原因。

写作的旧 v1 快照保留历史输入裁剪、偏好注入和剩余候选语义。仅当服务端 `can_continue` 判断该类型有重放处理器且快照仍有效时才可继续；不能把底层 continue API 的存在当作所有任务都可恢复。

作品分析和个人画像保持 metadata_only，使用独立业务检查点/授权，不能从写作日志续接。取消或已经开始输出后失败不自动切换模型拼接内容。重试可能产生新的模型费用，按实际网络用量与未知状态判断，不能把失败当免费。

## 偏好、检索和隐私

普通写作允许支持该字段的入口显式选择偏好画像和注入强度。成人局部润色不接受这些字段；存在个人 XP 画像也不代表所有写作入口自动消费它。

检索默认使用 TF-IDF，可显式启用本地模型或远程 embedding。配置、数据外发和索引位置见 [检索配置](QWEN_EMBEDDING_INTEGRATION.md)。当前索引以章节摘要/事件为主，不是全库语义搜索或推荐向量化。

Provider 故障转移可能将同一创作输入发送给多个服务商。项目、草稿、候选和偏好属于私人数据；密钥和原始输入不要进入日志。写作旧任务的保留方式与分析 metadata_only 不同，删除任务后也不能保证备份/WAL 物理抹除。

## 数据与维护

- 项目/章节/聊天的组合更新使用事务，失败保留原有有效状态；章节和 metadata 更新不可先读后无条件覆盖。
- 检索重建失败回滚，保留原索引；向量响应必须完整对应输入索引、具有一致维度和有限值。
- 写作表在切换 main 时保留。生产切换前仍应做一致数据库/归档/配置备份，旧版本回退不能绕过新版认证或 revision。
- 写作页面使用共享持久会话、CSRF、CSP nonce 和静态 CSS。新增模板类名需要重建样式。
- 写作检索在业务事务外计算分词/向量，再用短事务核对章节 revision、正文、摘要/事件与模型配置后发布。旧版本迟到结果直接丢弃；空内容清理索引不调用模型。细节见 [实施计划 W1](IMPLEMENTATION_PLAN.md)。

自动回归验证协议、事务和页面行为；真实模型创作质量、费用和手机体验见 [项目现状](STATUS.md) 的外部验收边界。主分支不提供本页所列写作路由。
